# Planning analysis

Understand the problem before proposing work.

## Procedure

1. Restate the goal in one sentence.
2. List stakeholders and users.
3. List constraints: time, budget, stack, compatibility, compliance.
4. List dependencies: systems, teams, data, approvals.
5. List assumptions and open questions.
6. Define observable acceptance criteria.
7. Classify risk: low, medium, high.
8. Recommend the next planning step.

## Rules

- Do not propose implementation detail yet.
- Separate facts from assumptions.
- Make every criterion testable.
- Surface blockers early.
- Keep the analysis proportional to the task.

## Output

Goal, constraints, dependencies, assumptions, acceptance criteria, risk, next step.
